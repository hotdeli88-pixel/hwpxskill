# 검수와 보고

`fill`·`exam`은 저장 직후 `check`를 자동으로 돈다. 따로 할 때:

```bash
hwpx check 결과.hwpx              # 구조 + 개인정보 + 표기법 + PDF
hwpx check 결과.hwpx --render none   # PDF 없이
hwpx validate 결과.hwpx           # 구조만
```

## 1. 구조 검사 (항상)

| 항목 | 오류면 |
|---|---|
| ZIP: `mimetype` 첫 항목·무압축, 필수 파일, manifest 목록 | 한글이 파일을 못 엶 |
| XML 형식, 네임스페이스 접두어(`hp:` `hh:` …, `ns0:` 금지) | 한글이 못 엶 |
| 스타일 참조(charPr·paraPr·borderFill·style ID)와 `itemCnt`, 글꼴 참조가 번호인지 | 글자가 깨지거나 못 엶 |
| 표 `rowCnt`/`colCnt`, 셀 주소 중복 | 표가 깨짐 |
| 짝 없는 누름틀 | 필드가 깨짐 |
| 경고: 남은 `{{자리표시}}`, 수식 문법 | 채우기 빠짐 |
| 정보: 빈 누름틀 목록 | 일부러 비운 것인지 확인 |

구조 오류가 나오면 결과를 넘기지 말고 원인을 고친다 (대부분 값이나 명령 사용법 문제 — 엔진 오류로 보이면 그 내용을 사용자에게 그대로 알린다).

## 2. PDF 눈으로 보기 (렌더가 될 때)

Windows는 한글, Mac·Linux는 rhwp가 `결과.pdf`를 만든다. **모든 쪽을 직접 본다** (Claude Code: Read 도구로 PDF). 볼 것:

- 채운 글이 칸을 넘치거나 잘리지 않는지, 표가 쪽을 넘어가며 이상하게 나뉘지 않는지
- 줄 앞 부호(□ ○ -)와 둘째 줄 들여쓰기가 가지런한지, 예시 셀과 같은 모양인지
- 체크(☑)가 맞는 자리에 들어갔는지, `○○○` 등 확인 표시가 남은 곳
- 수식 모양(분수·근호·첨자), 보기 ①~⑤ 배치
- 쪽 수가 양식보다 갑자기 늘지 않았는지 (늘었으면 내용이 너무 긴 것)

미리보기 엔진 차이: rhwp는 한글과 줄바꿈 위치가 조금 다를 수 있다. 판단이 애매하면 "한글에서 열어 최종 확인해 주세요"라고 덧붙인다. 렌더 엔진이 없으면 HWPX만 전달하고 같은 안내를 한다.

## 3. 개인정보 (경고만)

본문 글자만 검사한다: 주민등록번호(생년월일 검사), 외국인등록번호, 휴대전화, 개인 이메일, 카드번호(Luhn), 계좌번호·여권·운전면허(라벨 문맥). 기관 대표번호·`go.kr` 등 공공 이메일은 `정보`로만 표시한다.

- 결과를 막지 않는다. 경고가 있으면 보고에 적는다.
- 사용자가 원하면: `hwpx privacy redact 결과.hwpx -o 결과_가림.hwpx` — 서식을 유지한 채 가리고, 미리보기 글·그림도 정리한다. 가린 뒤에도 남은 것이 있으면 알려 준다.
- 공개 저장소·메일로 내보내기 전에는 가린 사본을 권한다.

## 4. 표기법

`표기법: 오류 N건` — 오류는 고친다 (값 JSON을 고쳐 다시 `fill`). 경고는 양식 원문에서 온 것일 수 있으니 채운 부분만 판단한다. 자세히: `hwpx lint 결과.hwpx`.

## 5. 사용자에게 보고하는 틀

```
완성: 결과.hwpx (PDF: 결과.pdf, 3쪽)
- 채운 곳 23곳 (누름틀 7, 표 12, 명단 4명 — 행 2개 추가)
- 확인이 필요한 값: 문서번호(○○과-0000), 시행일(0000. 0. 0.), 담당자 연락처
- 남은 빈칸: 없음 / 비고란 3칸은 비워 둠
- 검사: 구조 정상, 표기법 오류 0건, 개인정보 경고 1건(휴대전화 1건 — 가린 사본 필요하면 말씀해 주세요)
- PDF 확인: 2쪽 표가 쪽 끝에서 나뉨(원본 양식과 같음)
```

지어낸 값이 없는지 마지막으로 되짚는다: 사용자 자료에 없던 이름·숫자·날짜가 들어갔다면 `○○○`로 바꾸거나 확인을 받는다.
