# hwpxskill v2 요구사항 명세

> 2026-09-28 요구사항 인터뷰 결과를 정리한 문서입니다. 구현은 이 문서를 기준으로 진행합니다.
> 참고 구현: [kordoc](https://github.com/chrisryugj/kordoc) (MIT), [rhwp](https://github.com/edwardkim/rhwp) (MIT)

## 0. 목표와 범위

**목표**: 이미 있는 HWPX 양식(공문서·학교 문서·신청서·시험지)에 들어갈 내용을 Claude가 작성하고, 원본 서식을 그대로 살려 채워 넣는 스킬.

| 포함 | 제외 (이번 범위 아님) |
|---|---|
| 양식 분석, 양식 채우기(1순위) | 빈 문서에서 일반 문서 생성 (시험지만 예외) |
| 서식을 갖춘 셀·본문 내용 작성 | 새 양식 설계, 완성본 → 템플릿 변환 |
| 다른 표에 표 스타일 입히기 | 표 통째 복제, 표 스타일 프리셋 저장 |
| 한글 수식 스크립트 입력·읽기·수정 | LaTeX 수식 입력 |
| 시험지 (양식 채우기 + 내장 스타일 생성) | 시험지 그림 삽입, 정답·해설지 생성 |
| 공문서 표기법·개조식 문체 검사 | |
| 개인정보 경고 + 요청 시 가리기 | |
| .hwp 입력 자동 변환, HWPX+PDF 출력, 자동 검증 | |

## 1. 실행 환경

- **도구**: 로컬 PC의 Claude Code, Antigravity 등 다른 에이전트 도구 (특정 도구에 묶이지 않도록 SKILL.md + 명령줄 엔진 구조)
- **OS**: Windows + 한글 2022 이상, Mac + 한글 for Mac (+ rhwp)
- **엔진**: Python 3.9+ 표준 라이브러리만 사용 (pip 설치 없이 동작). Windows 한글 자동화만 선택 의존성(pywin32)
- **설치 방식**
  - Claude Code 플러그인 마켓플레이스: `/plugin marketplace add hotdeli88-pixel/hwpxskill`
  - 스킬 폴더 복사 (Antigravity 등)
  - pip 패키지 (`pip install hwpxskill`, PyPI 배포 준비)

## 2. 엔진 원칙 (kordoc 방식 이식)

1. **원본 문자열 부분 교체(splice)**: XML을 DOM으로 다시 조립하지 않는다. 바뀐 부분만 원문 문자열에서 교체해 네임스페이스 접두어·선언·속성 순서를 1바이트도 건드리지 않는다.
2. **ZIP 보존 재작성**: 원래 엔트리 순서·압축 방식·시간 정보를 유지한다 (`mimetype` 첫 번째·무압축 자동 유지).
3. **줄 배치 캐시 제거**: 내용이 바뀐 섹션의 `<hp:linesegarray>`는 모두 지운다 (일부만 남기면 한글이 변조 경고를 띄움).
4. **원본 불변**: 입력 파일을 덮어쓰지 않고 항상 새 파일로 저장한다.
5. **출처 표기**: kordoc·rhwp에서 가져온 방식과 규칙은 NOTICE에 MIT 출처를 적는다.

## 3. 기능 요구사항

### 3.1 양식 분석 (`analyze`)
- 채울 수 있는 곳을 모두 목록(JSON 스키마)으로 낸다: 누름틀, `{{키}}`, 표의 라벨→값 칸, 명단표(머리행+데이터행), 본문 `라벨: 값`, 체크박스(□), 괄호 빈칸, 예시가 채워진 셀, 수식.
- 섹션 순서는 `content.hpf`의 spine을 따르고, 중첩 표를 바깥 표와 구분한다.
- 각 항목에 위치(섹션·표·행·열), 현재 글자, 서식 정보를 붙여 Claude가 내용을 설계할 수 있게 한다.

### 3.2 양식 채우기 (`fill`) — 1순위
- **누름틀**: 필드 이름이 정확히 같으면 채운다.
- **`{{키}}` 자리표시**: 글자 서식 때문에 여러 조각(run)으로 나뉘어 있거나 줄바꿈 뒤에 있어도 치환한다.
- **표 라벨 옆 칸**: '성명' 같은 라벨 칸의 오른쪽 칸에 값을 넣는다.
- **명단표**: 머리행 아래 데이터 행에 배열 값을 차례로 넣는다. 데이터가 양식의 행보다 많으면 **마지막 데이터 행 서식을 복제해 행을 추가**하고, 남는 빈 행은 그대로 둔다.
- **본문 라벨·체크박스·괄호**: `신청인: ___` 뒤, `□남 → ☑남`, `일반(  )통`.
- **미리보기**(`--dry-run`): 어떤 값이 어디에 들어갈지 먼저 보여준다.
- **보고**: 채우지 못한 키, 남은 빈칸, 남은 자리표시를 목록으로 알려준다.

### 3.3 서식을 갖춘 내용 작성 (셀·본문)
- **입력**: Claude가 쓴 일반 텍스트 줄. 항목부호(□ ○ - · ※ 1. 가. 1) 가) 등)와 들여쓰기로 단계를 나타낸다. 마크다운 강조 문법은 쓰지 않는다.
- **서식 출처 우선순위**
  1. 같은 셀에 예시로 채워진 내용 → 부호별(□/○/-) 문단 모양·글자 모양을 익혀 같은 부호 줄에 입힌다.
  2. 같은 표·문서에서 예시로 채워진 셀·문단
  3. 예시가 없으면 **첫 문단 서식**(글꼴·크기·줄간격)을 따르고 단계별 들여쓰기·내어쓰기만 더해 둘째 줄이 부호 뒤 글자에 맞춰 정렬되게 한다.
- 예시 글은 새 내용으로 바꾼다.

### 3.4 표 스타일 복제 (`apply-table-style`)
- 원본 표(같은 문서 또는 다른 문서)의 **스타일만** 대상 표에 입힌다. 대상 표의 내용은 바꾸지 않는다.
- 옮기는 항목: 테두리(선 종류·굵기·색), 셀 배경, 글꼴·크기·굵기·색, 문단 정렬, 세로 정렬, 셀 여백, 열 너비 비율.
- **역할 기준 매핑**: 머리행, 라벨 열(첫 열), 본문, 합계행(합계·계·소계), 바깥 테두리·안쪽 선. 행·열 수가 달라도 적용된다.
- 다른 문서 간 복제 시 글꼴·글자 모양·문단 모양·테두리 정의를 대상 `header.xml`로 옮기며 ID를 새로 매기고 중복을 없앤다.

### 3.5 수식
- **입력 문법**: 한글 수식 스크립트만 받는다 (예: `{a+b} over {2}`, `sqrt {x}`, `sum from {k=1} to {n} k`). LaTeX 변환은 하지 않는다.
- **위치**: 문장 속 인라인(글자처럼 취급, 주변 글자 크기에 맞춤), 독립된 줄.
- **읽기·수정**: 문서의 수식을 스크립트 그대로 목록으로 보여주고, 번호나 내용으로 찾아 다른 스크립트로 바꾼다.
- **검사기**: 저장 전에 중괄호 짝, 알 수 없는 명령어를 검사한다.
- **참고 문서**: 한글 수식 스크립트 문법 요약을 스킬에 넣는다.

### 3.6 시험지
- **양식이 있으면**: 예시 문항의 서식을 따라 문항·배점·보기·수식을 채운다. 2단 설정이 없으면 2단으로 바꾼다.
- **양식이 없으면**: 내장 시험지 스타일로 새로 만든다 (A4, 2단, 머리 표(학년·반·번호·성명 등), 문항 번호 자동, `[3점]` 배점 표시).
- **보기 ①~⑤ 자동 배치**: 보기 길이에 따라 한 줄(5개)·두 줄(3+2)·다섯 줄로 가지런히 배치한다. 보기 안 인라인 수식을 지원한다.
- **입력**: 문항 목록 JSON (문항 글, 배점, 보기, 수식).

### 3.7 공문서 표기법·개조식 문체 검사 (`lint`)
- kordoc의 공문서 표기법 22개 규칙(날짜 `2026. 9. 28.`, 시간, 금액, `붙임`·`끝.`, 물결표, 외래어·차별어, AI 문체 등)과 개조식 문체 12개 규칙을 옮긴다.
- Claude가 쓴 값을 채우기 **전에** 검사해 고치고, 완성 문서 전체도 검사할 수 있다.

### 3.8 개인정보 검사
- XML 태그·속성은 빼고 **본문 글자만** 검사한다. 기관 대표번호·업무 이메일 같은 공개 연락처는 허용한다.
- 결과를 막지 않고 **경고만** 한다.
- 요청하면 서식을 유지한 채 가린 사본(`redact`)을 만든다.

### 3.9 HWP 입력
- `.hwp`를 받으면 HWPX로 자동 변환한 뒤 작업한다: Windows는 한글(COM 자동화), Mac은 `rhwp export-hwpx`. 원본은 고치지 않는다.

### 3.10 결과물과 검증
- **결과물**: HWPX + PDF.
- **항상 자동 검증**
  1. 구조 검사(항상): ZIP 구조, manifest, XML 형식, 네임스페이스 접두어, 스타일 참조(IDRef) 무결성, `itemCnt`, 줄 배치 캐시, 남은 자리표시, 수식 문법.
  2. 렌더(가능할 때): Windows는 한글, Mac은 rhwp로 PDF를 만들고 Claude가 페이지를 직접 보고 깨짐·넘침을 확인한다.
  3. 결과 보고: 채운 항목, 지어낸 값이 없는지, 남은 빈칸, 표기법·개인정보 경고.

## 4. 작업 절차 (SKILL.md 5단계)

| 단계 | 하는 일 |
|---|---|
| 1. 분석 | `analyze`로 채울 곳·예시 서식·수식 파악 |
| 2. 내용 작성 | 서술형은 Claude가 작성, 이름·날짜·금액·연락처 등 **사실 정보는 사용자에게 확인**하거나 `○○○`로 표시. 작성 후 `lint` |
| 3. 서식 | 예시 서식 매칭, 필요하면 `apply-table-style` |
| 4. 조립 | `fill`(미리보기 → 실제 저장), 수식 삽입 |
| 5. 검수 | `validate` + 렌더 확인 + 개인정보·남은 빈칸 보고. Claude Code에서는 보조 에이전트를 선택적으로 사용 |

## 5. 기존 코드 처리

- 기존 명령어·API 호환은 유지하지 않는다 (PyPI 미배포, 외부 사용자 없음). 명령어 이름만 비슷하게 둔다.
- 이름뿐이던 5-에이전트 오케스트레이터와 쓰이지 않던 프롬프트는 SKILL.md의 실제 작업 단계로 바꾼다.

## 6. 테스트

- kordoc·rhwp의 공개 서식(일반·간이 기안문 등)과 직접 만든 픽스처(계획서, 명단표, 시험지)로 테스트한다.
- 저장소가 공개이므로 개인정보가 들어간 실제 문서는 올리지 않는다.

## 8. 사용자가 직접 해야 하는 일

- **PyPI 배포**: PyPI 계정에서 Trusted Publishing 설정 (배포 워크플로는 준비해 둠)
